# 北京地图的生成脚本

`js/geo_bj.js` 与 `js/data_bj.js` 里的地理与坐标由这里的脚本生成；年代表（道路通车、地标落成、人口与造价、任务锚点）是人工整理的数据，写在 `js/data_bj.js` 里。

坐标约定：格 250 m，左上角原点 `lon0 = 116.040, lat0 = 40.160`，`kx = 341.66, ky = 443.84`，地图 `W = 240, H = 209`（W、H 必须是 `CFG.ZONE = 4` 的整数倍）。

范围以现在的**六环路**为界（约 60 × 52 km）：西到西六环（含石景山苹果园），东到东六环（含通州城区），北到北六环（含回龙观、天通苑、首都机场），南到南六环（含黄村、亦庄）。

## 重新生成

```bash
python3 fetch.py        # 分块（8×6=48 块）从 Overpass 抓取水系/道路/铁路/绿地 + 区与街道界/地名/车站节点（约 1–2 小时，支持断点续传）
python3 extract.py      # 合并分块、拼接关系多边形 → features.json
python3 build_geo.py    # 投影、简化、编码 → ../js/geo_bj.js
python3 gen_stations.py 苹果园 古城 …   # 查 OSM 车站节点经纬度，用于校准 data_bj.js 站点坐标
```

依赖：`shapely`、`opencc`（`pip3 install opencc-python-reimplemented`）。

北京是内陆城市，没有海岸线，因此不需要 `make_sea.py`；河流与湖泊直接由 OSM 的 `natural=water` / `waterway` 要素得到。

## 验证脚本（不需要浏览器）

```bash
node smoke.js 2026      # 生成地图、区域统计、逐年推进、任务锚点检查
node simtest.js 2026    # 按月推进人口 → 建出行模型 → 全网拥堵与主要道路 v/c
```

## 设计约定（与深圳/广州地图不同的地方）

1. **一次性开图、不屏蔽任何区域**：所有 `regions` 不带 `open` 字段（`open == null` 即开局开放），
   六环内每个格子都归属某个区级区域（`district` 匹配 OSM 区界），未匹配街道名的格子由区级兜底，
   `defaultRegion` 也开局开放。区域仍按真实区/街道划分，只影响开发形态，不再按年份解锁。
2. **站点坐标来自 OSM**：`initialNetwork` 与任务锚点的经纬度取自 `mstations.json`
   （OSM 的 `railway=station` 节点），避免手写坐标造成几百米偏差。
3. **地铁轨道不进底图**：`extract.py` 只收 `railway=rail`（普速/高铁），OSM 的现代地铁线不落地，
   1990 年后的真实地铁由玩家建设（史实只作为任务参考）。

## 来源与日期

- 地理：OpenStreetMap（© OpenStreetMap 贡献者，ODbL），按 250 m 网格投影，地名转简体。
- 开启既有地铁：1 号线苹果园—复兴门 12 站（1987-12-28 拆分后独立运营）、2 号线环线 18 站（1987-12-28 成环）。
  站点坐标取自 OSM 车站节点。
- 线路开通年份与站序：见 `北京地铁史实.md`（维基百科《北京地铁》条目，本机直连不可达，经 Wikiwand 镜像与百科快照核实）。
- 道路通车年份、地标落成年份、车站与机场启停年份为史实参考（位置与范围近似）。
- 人口就业分布、增长曲线、造价、票价与设施规模为估算；2026 年 10 月之后为模拟。
